# Everyday UI 1.0 release candidate

## Try the candidate from source

Use Node 24 and npm. The React adapter supports React and React DOM 18 or 19. The Svelte adapter uses Svelte 5.20 or newer within major version 5. Both use Tailwind CSS 4 and a bundler that compiles package TypeScript and, for Svelte, Svelte source. The CLI and tokens can be used independently.

```sh
git clone https://github.com/weuxstudio/everyday-ui.git
cd everyday-ui
git switch feat/v1-adapter-parity
npm ci
npm run build
npm run test:packages
npm run build:examples
node tests/serve.mjs
```

Open [the installed React signup](http://127.0.0.1:4173/tests/dist/react/), [the installed Svelte signup](http://127.0.0.1:4173/tests/dist/svelte/) or [the gallery](http://127.0.0.1:4173/examples/dist/patterns.html). The consumer check packs all five workspaces, installs each adapter in a separate temporary npm project, copies the brief and signup pattern, generates its theme and builds the app. The generated entry pages stay in `tests/dist`. For the review, run these commands in a second terminal from the checkout.

```sh
npx playwright install chromium
node packages/shots/bin/everyday-shots.mjs http://127.0.0.1:4173 /tests/dist/react/ /tests/dist/svelte/
```

To install into an existing project before publication, build the checkout and generate tarballs there.

```sh
mkdir -p artifacts
npm pack -w @everyday-ui/tokens -w @everyday-ui/react -w @everyday-ui/svelte --pack-destination artifacts
```

In the consuming project install the tokens tarball and the matching adapter tarball together with npm. Import Tailwind, the generated theme and the adapter stylesheet in that order. Use the adapter source path in the Tailwind `@source` directive, relative to the stylesheet. See the [React setup](../skills/everyday-ui/references/stack-react.md) and [Svelte setup](../skills/everyday-ui/references/stack-svelte.md).

## Adapter contract

All rows apply to both adapters in 1.0.0-rc.1. Native events and attributes use their framework's spelling. React supports controlled values, initial defaults and callbacks. Svelte uses initial values and bindings. Rich content uses React nodes or Svelte snippets.

| Export | Main inputs and defaults | Observable behavior |
| --- | --- | --- |
| Button | variant secondary, size md, type button, loading, disabled | Named button, Enter/Space activation, repeat presses ignored while busy |
| Field | label, value, hint, error, required, optional, chars | Linked label, error and hint, invalid state, native text entry |
| PasswordField | label, value, rules, purpose new | Masked initially, Show/Hide retains value, password-manager autocomplete and live rule feedback |
| Checkbox | label, checked, hint, error | Native checkbox with Space toggle and linked descriptions |
| RadioGroup | name, legend, options, value, hint, error, id | Named group, one selection, arrow-key navigation, focusable first input |
| SegmentedControl | label, options, value, onValueChange | First option by default, native radio keyboard interaction |
| Switch | label, checked initially false, onCheckedChange | Named switch, immediate state change |
| Stepper | label, value 0, min 0, max 99, step 1 | Labelled input, keyboard-accessible decrease/increase, bounds enforced |
| ProgressSteps | steps, zero-based current, onStepClick | Current step announced, completed steps can be revisited, compact phone display |
| ErrorSummary | errors, title, optional submitAttempt | Focus on failed submit, links focus the invalid field, empty summary disappears |
| EmptyState | title, description, action, secondary, icon | Named explanation and available recovery action |
| Badge | tone neutral, icon, children | Status as text with optional decorative icon |
| Card | as section, title, description, actions, elevation flat | Heading names the container, actions belong to the card |
| Dialog | open, title, description, footer | Native modal, escape closes, keyboard focus returns to trigger |
| BottomSheet | open, title, dismissible true, closeOnBack true | Native modal with close button, scrim and browser-back dismissal |
| RequirementMark, FieldHint, FieldError | required/optional, id, content | Optional text, linked hint, visible error icon and message |

Both `/motion` entry points expose MotionProvider, Reveal, Collapse and AnimatedList. Svelte takes a CSS string on MotionProvider and a renderItem snippet on AnimatedList. Use `viewTransition(update)` in Svelte and `useViewTransition()` in React. The shared `@everyday-ui/tokens/motion` export reads inherited motion tokens. Reduced motion and the absence of the browser View Transition API are supported.

| Pattern | React | Svelte |
| --- | --- | --- |
| Signup and onboarding | SignupOnboarding.tsx | SignupOnboarding.svelte |
| Pricing | Pricing.tsx | Pricing.svelte |
| Dashboard | Dashboard.tsx | Dashboard.svelte |
| Settings | Settings.tsx | Settings.svelte |
| Checkout | Checkout.tsx | Checkout.svelte |
| Lists and tables | ListsTables.tsx | ListsTables.svelte |
| Mobile app | Shared HTML/CSS/JS blueprint | Shared HTML/CSS/JS blueprint |

## Migrating from 0.6

Update the tokens and adapter together. When copying a pattern, include its sibling `data.ts` and, for Svelte, the local Svelte components it imports. Increment `submitAttempt` once per submit and pass it to ErrorSummary to handle repeated errors. Existing callers can omit it and retain error-count-based focus. Review scripts now replay configured actions in the reduced-motion and zoom variants. Use local fixtures or mocked APIs when an action writes data.

The public compatibility surface comprises the package exports, documented component props and events, semantic CSS variables and token names, and documented theme, lint and shots CLI flags and configuration fields. In 1.x, additions are minor changes. Removals and incompatible behavior changes require a major release.

## Release checks

1. From a clean checkout run CI, including the packed consumer installs, Chromium/Firefox/WebKit interaction tests and the pattern review. Inspect the contact sheet and focus order at phone/desktop widths, both color schemes, reduced motion and 200% zoom. Record the commit and findings with the release candidate.
2. On Windows with NVDA/Firefox and on macOS with VoiceOver/Safari, run the signup and Settings dialog in **each** framework. Submit twice, follow the error link, correct both fields and complete signup. Open the dialog using the keyboard, listen for its name and description, navigate its controls, dismiss with Escape and confirm focus returns. Record browser and AT versions, result and any blocking issue.
3. In two fresh agent sessions with the installed skill, request “Build an account registration for a small design studio” once per framework. Check the project brief, generated theme, labelled fields, submit feedback, completion and saved review. Record any undocumented manual intervention.
4. With the release owner's npm identity verify write access to the five scoped packages or permission to create them. Confirm package, peer, plugin and lockfile versions, changelog, tarball contents and CI commit before tagging the final 1.0.0 and publishing.
